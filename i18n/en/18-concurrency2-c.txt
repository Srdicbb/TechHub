Atomic operations and Interlocked
@c8bb1ab7da
An atomic operation runs completely or not at all, with no interruption between steps. `Interlocked` uses special processor instructions for addition, exchange and compare-and-swap, so it works without a lock.
@2a0263b09d
`Interlocked.Increment(ref x)` reads, adds and writes as one indivisible processor operation.
@89fb35c98c
**Compare-and-swap** (`Interlocked.CompareExchange`): write the new value only if the current one equals the expected one. If it does not, someone got there first, so read again and retry.
@d2df43f0f6
A CAS loop is the basis of lock-free structures such as `ConcurrentQueue` and `ConcurrentStack`. Under heavy contention the number of retries grows.
@c60a866b52
Reading and writing an `int` or a reference are atomic by themselves; a `long` only in a 64-bit process. `volatile` and `Volatile.Read/Write` guarantee visibility and ordering, but not atomicity of compound operations.
@7a21532e95
Only a single field is atomic. Two variables that must change together need a `lock`.
