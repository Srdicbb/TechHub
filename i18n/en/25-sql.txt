Index: a B+ tree
@71d365292c
An index in SQL Server is a B+ tree of 8 KB pages. A search by key (a **seek**) goes through a few levels down to a leaf, and without a suitable index the database reads all pages in order (a **scan**).
@e6bc9a8eed
The root and inner nodes hold key ranges; the leaves hold the rows (clustered) or the key and a pointer to the row (nonclustered).
@9599f1e380
The depth grows logarithmically: millions of rows fit into 3 to 4 levels, so a seek is just a few page reads.
@3d6460c38f
The leaves are linked, so a range query (`BETWEEN`) is one seek to the start followed by a walk along the leaves.
@a4864f068a
A nonclustered index without all the query's columns does a **key lookup** for every row. `INCLUDE` columns make a covering index.
@ab91371ed6
An index speeds up reads and slows down writes: every INSERT, UPDATE and DELETE changes the tree too.

Isolation levels
@6268185723
