The memory and latency hierarchy
@200e2892c0
The farther data is from the processor, the more expensive it is to reach: from a nanosecond in the L1 cache to hundreds of milliseconds across an ocean. Caching moves data to a faster level.
@5b2e89f874
The differences are orders of magnitude: RAM is about 100× slower than L1, and a call to Redis in the same region about 5,000× slower than RAM.
@37c5db493b
That is why one extra database call inside a loop costs more than thousands of operations in memory.
@0febfadafe
Every cache level is a trade-off: a faster level is smaller and more expensive, and it keeps a copy that can go stale.
@f1236b26c8
Locality: data that is accessed together should be stored together (an array of structs instead of a web of objects across the heap).

Cache-aside and TTL
@0e33c07166
The application asks the cache first. If the data is not there (a **miss**), it reads from the database and writes it into the cache with an expiry time (**TTL**), so the next request gets a fast response (a **hit**).
@6e251d5bcf
Cache-aside (lazy loading): the application fills the cache, and only with data that is actually requested.
@9481a997f0
The TTL limits how long data may be stale. A shorter TTL is fresher, but more requests go to the database.
@0ed041ba52
On a change: write to the database, then **delete** the key from the cache (invalidation). The next read fills in the fresh value.
@63e5d7ecef
The hit ratio (hits divided by all requests) is the main metric: 95% means the database sees 5% of the traffic.

Eviction: LRU and LFU
@0441e4ab8a
A cache has limited capacity. When it fills up, something has to go: **LRU** evicts what has not been used for the longest time, and **LFU** what is used least often.
@4344e1c1d0
LRU quickly follows changes in what is popular, but a single scan of all keys evicts the whole working set.
@dfe61403e6
LFU keeps the steady favorites and resists scans, but slowly forgets keys that were once popular.
@64994d799a
Redis has both policies (`allkeys-lru`, `allkeys-lfu`) and variants only for keys with a TTL (`volatile-*`).
@2c10efd478
LRU in O(1): a hash map plus a doubly linked list. On access the node goes to the front, and eviction happens from the back.
