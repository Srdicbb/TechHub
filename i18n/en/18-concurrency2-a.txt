@b2215b0a42

@ecb1096c94

@252291e055

@f20018d00c

CPU, cores and cache
@e43e7efa85
A core runs one thread at a time (two with hyper-threading). Data travels from RAM through the L3, L2 and L1 caches in 64-byte blocks, and that often determines the speed of concurrent code more than the algorithm itself.
@cead72cd5b
`Environment.ProcessorCount` returns the number of **logical** cores: with hyper-threading (SMT) one physical core looks like two. In a container it returns the CPU limit.
@1eb7a15526
Every core has its own L1 and L2 cache, and L3 is shared. An L1 access takes about 1 ns, RAM about 100 ns. More on that in [[latency]].
@e566b7cdab
The cache works in 64-byte blocks (a **cache line**). When one core writes to a line, the copies of that line in other cores become invalid.
@ed92beb6c4
**False sharing**: two threads write to different variables that lie in the same line, so the line keeps moving between cores. The code is correct, but several times slower.
@378ae85ab1
More threads than cores does not speed up CPU work: the threads take turns, and every switch and a cold cache cost.

The OS scheduler and context switches
@f124a78dbd
The operating system decides which thread runs on which core. A thread gets a short time slice (a quantum), then the scheduler interrupts it and lets the next ready one run. A thread waiting for I/O or a lock does not use a core at all.
@1694c1e1cc
A thread is in one of three main states: **running** (on a core), **ready** (waiting for a free core) or **blocked** (waiting for I/O, a lock, `Sleep`).
@f24780d6b0
The scheduler is preemptive: when the slice expires or a higher-priority thread appears, the current thread is interrupted without asking.
@c4e1c8c8e3
**Context switch**: save one thread's registers, load another's. It takes microseconds, but afterwards the cache is cold.
@53aa328aa8
The CLR does not assign threads to cores; the OS does. .NET decides only how many threads exist (the ThreadPool) and what they do.
@46715bc584
More ready threads than cores means waiting in a queue: CPU work does not speed up, it only switches more often.
