TCP/IP layers and the path of a packet
@98b98685f0
The network is built in layers. Each layer solves one problem and adds its own **header** in front of the data of the layer above: an HTTP message goes into a TCP segment, the segment into an IP packet, the packet into an Ethernet or Wi‑Fi frame. Along the way routers read only the IP header, and the server removes the headers in reverse order.
@fd90f538b0
**Application** (HTTP, DNS, gRPC): messages the program understands.
@26af98d502
**Transport** (TCP, UDP): from process to process, through ports. TCP adds ordering, acknowledgements and retransmission; UDP only a port and a checksum.
@f8ab76ca75
**Internet** (IP): from machine to machine, through addresses and routers. It guarantees neither delivery nor ordering; the TTL keeps a packet from circling forever.
@5e9e375fb0
**Link** (Ethernet, Wi‑Fi): only to the next device, through MAC addresses. The frame is rebuilt at every hop.
@2599f1ec94
A port distinguishes processes on the same machine: 443 is HTTPS, 5432 PostgreSQL. The addresses and ports of both sides together identify one TCP connection.
@390aebcb9e
The OSI model has seven layers; in practice the four of the TCP/IP model are used, and the labels L4 and L7 (for example for load balancers) come from OSI numbering.

TCP and UDP: handshake and reliability
@fa78cb0972
Before any data, **TCP** opens a connection (the **handshake**: SYN, SYN-ACK, ACK), numbers the bytes, waits for acknowledgements and retransmits what was lost, so the application gets everything, in order. **UDP** just sends datagrams: no connection, no acknowledgements, no ordering, but also no waiting.
@04c0f79a7c
The handshake costs one RTT before the first byte. That is why connections are kept open (keep-alive) and reused (connection pooling).
@beded4db0c
Acknowledgements are cumulative: ACK 4 means "I have everything up to 3, the next one is 4". When a segment is missing, the receiver keeps later segments in a buffer and does not hand them to the application until the gap is filled.
@e83740c11a
A lost segment is sent again when the timer expires (RTO) or earlier, after three duplicate acknowledgements (fast retransmit).
@5cadf85299
The window determines how much unacknowledged data may be in flight; congestion control shrinks it when there are losses.
@0b3af2baea
Closing happens with FIN in both directions, and the side that closes first keeps the connection in the TIME_WAIT state for a while.
@41ff8bb9d9
UDP is used by DNS, live voice and video, games and QUIC (HTTP/3): wherever a late packet is worse than a lost one, or where the protocol above solves reliability itself.

DNS: from a name to an IP address
@aa9a3e6d6a
Before any connection, the client has to turn a name (`api.shop.rs`) into an IP address. It asks a **recursive resolver** (the provider's, 1.1.1.1 or DNS in the cluster), and if the answer is not in its cache, the resolver goes step by step: the **root** server refers it to the **TLD** (`.rs`), the TLD to the domain's **authoritative** server, which gives the final answer. Every answer has a **TTL** and is cached.
@2ea1d48362
Caches exist in several places: the browser, the operating system, the resolver. Most queries are answered from a cache in a few milliseconds.
@6c7b03a756
The TTL is a trade-off: a long TTL means fewer queries, but a change of IP address reaches everyone only when the old entries expire.
@e8afc927f9
Before a migration or a failover the TTL is lowered days in advance, so that the later change is fast.
@c78cac3dc3
DNS can also distribute traffic: several A records (round robin), an answer by client location (GeoDNS) or by service health (Azure Traffic Manager).
@6b6771815d
In Kubernetes, CoreDNS gives names to services: `katalog.prod.svc.cluster.local` leads to the service's ClusterIP.
